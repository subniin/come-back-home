# 컴백홈 시스템 & 통신 아키텍처 정의서 (초안)

| 항목 | 내용 |
|---|---|
| 버전 | v0.2 (초안) |
| 작성 | 김수빈 |
| 작성일 | 2026-09-23 |
| 상태 | 검토 전 — 부품 목록·BLE 세부 필드는 회의에서 변경 가능 |

> 이 문서는 **역할과 인터페이스**를 정의하는 문서다. 특정 부품 모델명은 참고용 예시이며, 부품이 바뀌어도(MOSFET 종류, 배터리 용량 등) 이 문서의 구조는 바뀌지 않도록 "부품이 무엇을 해야 하는가"를 기준으로 작성했다. 부품이 확정되면 9장 표만 갱신하면 된다.

> **v0.2 변경점**: ESP32를 손목이 아니라 허리(폰 옆)에 1개로 통합. 손목엔 진동모터만 남긴다. 허리 유닛에서 각 손목까지 전선을 따로 뺀다 (손목-손목 간 배선은 없음 — 팔마다 독립된 짧은 배선).

## 1. 시스템 개요

구조대원이 허리에 스마트폰과 ESP32 유닛을 함께 착용한다. 손목에는 진동모터만 부착하고, 허리 유닛에서 각 팔을 따라 전선 하나씩 내려가 모터를 구동한다.

- **폰(허리)**: 위치·방향 계산, 모드 판정(실내/실외), 경로 저장, 역경로 계산. BLE central.
- **ESP32(허리, 폰과 별도 케이스)**: BLE 수신, 좌/우 진동모터 유선 구동, 전방 장애물 감지, 수동 모드전환 버튼. BLE peripheral 1대.
- **손목**: 진동모터 + 배선만. 전자부품(MCU, 배터리, 드라이버) 없음.
- **통신**: 폰 1대 — ESP32 1대, BLE 연결 1개.

> 이전 안(ESP32 손목당 1개, 무선 2연결)과 다른 점: 그 방식은 "양쪽 손목을 잇는 배선"이 불편해서 나온 대안이었는데, 이번 안은 손목끼리 잇는 배선이 아니라 **허리→각 팔**로 독립된 짧은 배선이라 몸통을 가로지르는 선이 없다. 손목 쪽 무게·부피도 진동모터 하나뿐이라 더 가벼워진다.

## 2. 컴포넌트별 책임

### 2.1 스마트폰 (허리)

| 기능 | 설명 |
|---|---|
| 위치 수집 | `LocationManager` 기반 GPS, `getAccuracy()`로 정확도 확인 |
| 방향 수집 | `TYPE_ROTATION_VECTOR` 기반 헤딩 계산 |
| 모드 판정 | GPS 정확도 기준 실내/실외 자동 전환 (+ 버튼으로 수동 전환) |
| 실내 위치추정 | PDR (걸음 감지 + 헤딩 추적), 분기 노드 그래프 생성 |
| 복귀 안내 | 목표 지점(실외) 또는 역경로(실내, 백트래킹)까지 방향·거리 계산 |
| BLE 통신 | ESP32에 안내 패킷 전송, 버튼 이벤트 수신 |
| 로깅 | 위치·센서·패킷 CSV 저장 (실험 데이터용) |

### 2.2 ESP32 유닛 (허리, 1대)

| 기능 | 설명 |
|---|---|
| BLE 수신 | 폰이 보낸 안내 패킷 수신 |
| 진동 출력 | 패킷의 `turnAngle` 부호로 좌/우 모터 중 구동할 쪽 결정, `distanceCm`으로 세기·패턴 조절 |
| 좌/우 모터 유선 구동 | 허리 유닛 내 MOSFET 드라이버 2채널 → 각 팔 배선 → 손목 모터 |
| 전방 감지 | 장애물 거리 측정, 임계값 이하 시 경고 패턴으로 오버라이드. 허리에 전방을 향하도록 장착 (몸 정면 고정이라 손목 장착보다 방향이 안정적) |
| 수동 전환 버튼 | 버튼 입력 시 폰에 모드전환 이벤트 전송 |

### 2.3 손목 (좌/우 각 1)

| 기능 | 설명 |
|---|---|
| 진동모터 | 허리 유닛에서 온 2가닥 배선(전원+접지)으로 직접 구동. 손목엔 능동부품 없음 |

> 배선은 팔 움직임을 따라가야 하므로 코일형(스프링) 케이블이나 소매 안쪽 경로로 느슨하게 고정하는 방식을 권장. 직선 배선이면 팔 굽힐 때 당겨서 걸릴 수 있음.

좌/우 구분은 펌웨어에서 어느 GPIO가 어느 팔로 가는지로 결정한다. 유닛이 1개라 `SIDE_LEFT`/`SIDE_RIGHT` 빌드 분기는 필요 없다.

## 3. BLE 통신 아키텍처

### 3.1 연결 구조

- 폰 = BLE Central, ESP32(허리) = BLE Peripheral 1대
- **BLE 연결 1개만 유지** (이전 안의 "동시 2연결" 불필요해짐)
- 연결 끊김 시 자동 재연결 시도, 재연결 중에는 양쪽 모터 모두 정지(안전 상태)

### 3.2 GATT 서비스 구조 (제안)

![GATT 서비스 흐름](GATT_구조도.svg)


| Characteristic | 방향 | 속성 | 용도 |
|---|---|---|---|
| `GuidanceChar` | 폰 → ESP32 | Write (or Write Without Response) | 안내 패킷 전송 (4장). ESP32가 부호로 좌/우 채널 선택 |
| `ButtonEventChar` | ESP32 → 폰 | Notify | 수동 모드전환 버튼 이벤트 |

| 구분 | UUID (128bit) |
|---|---|
| 안내 서비스 (Service) | `8c5a8775-542e-4447-a6d6-572d509d4938` |
| `GuidanceChar` | `8b2e38a4-d5bb-41a2-9378-7dd07e3d64dc` |
| `ButtonEventChar` | `383de663-08ec-437e-b633-58292aec7c29` |

> `GuidanceChar`를 Notify로 할지 Write로 할지는 팀 컨벤션에 맞춰 확정 (제안: 폰이 계산 주체이므로 Write가 더 명확함).

### 3.3 전송 주기

- 안내 패킷: 10Hz (제안값, BLE 지연 측정 후 조정)
- 버튼 이벤트: 이벤트 발생 시에만 (polling 아님)

## 4. 안내 패킷 정의 (폰 → ESP32)

```c
struct GuidancePacket {
    int16_t  turnAngle;   // 목표 방향까지 회전각(도). 음수=좌 모터 구동, 양수=우 모터 구동, 범위 -180~180
    uint16_t distanceCm;  // 목표/다음 분기 노드까지 거리(cm)
    uint8_t  state;       // 현재 모드
    uint8_t  seq;         // 패킷 순번 (0~255 순환). 지연·유실 측정용
};
```

| 필드 | 크기 | 확정 여부 | 비고 |
|---|---|---|---|
| `turnAngle` | int16 | 확정 | 부호가 곧 좌/우 모터 선택 기준. ESP32가 별도 해석 없이 바로 채널 결정 가능 |
| `distanceCm` | uint16 | 확정 | 전방 장애물 거리가 아니라 목표/노드까지 거리. 장애물 거리는 ESP32 로컬 센서가 자체 처리 |
| `state` | uint8 | 확정 (값은 5장) | |
| `seq` | uint8 | 제안 | BLE 지연·유실 측정(11월 필드테스트)에 필요해서 추가 제안. 팀 확인 필요 |

패킷 구조 자체는 이전 안(손목 2유닛)과 동일하다 — 좌우 분리가 BLE 레벨이 아니라 ESP32 내부(부호 판별 후 GPIO 채널 선택)에서 일어나는 점만 다르다.

## 5. 모드(state) 정의

| 값 | 모드 | 설명 |
|---|---|---|
| 0 | 대기 | 앱 실행 전/일시정지. 진동 없음 |
| 1 | 아웃사이드 | GPS 기반 안내 (안전지점 방향). 진동 있음 |
| 2 | 인사이드 (경로 기록) | 건물 진입 중 PDR로 이동 경로·분기 노드 기록. 진동 없음 |
| 3 | 백트래킹 (인사이드 복귀 안내) | 기록한 노드를 역순으로 따라가며 안내. 진동 있음 |

전환 조건: `Location.getAccuracy()` 임계값 기반 자동 전환 + 버튼 수동 전환. 신호 절단 시점 좌표를 PDR 원점으로 고정. 2 → 3 전환은 복귀 시작(버튼) 입력으로 한다.

ESP32의 진동 규칙: `state`가 1·3일 때만 진동하고, 0·2에서는 `turnAngle` 값과 관계없이 진동하지 않는다. 진동 중 `turnAngle=0`은 직진 안내다. (`state`를 둘로 나눈 이유: `turnAngle=0`이 "직진 안내"와 "안내 없음"을 구분하지 못하기 때문)

## 6. 버튼 이벤트 정의 (ESP32 → 폰)

```c
struct ButtonEvent {
    uint8_t eventType;  // 0: 짧게 누름(수동 모드전환), 1: 길게 누름(예약)
};
```

버튼은 허리 유닛에 물리적으로 붙어 있지만, 모드 판정 로직은 폰에 있으므로 버튼을 눌러도 반드시 BLE로 폰에 알려야 상태가 바뀐다. (이전 안에서 있었던 "버튼 위치 손목 vs 폰" 논쟁은 ESP32가 허리로 오면서 자연히 해소됨 — 버튼은 ESP32 쪽에 고정.)

## 7. 데이터 흐름 예시 (인사이드 → 백트래킹)

1. 폰: GPS 정확도 낮음 감지 → `state=2`(인사이드) 진입, PDR 시작, 분기 노드 기록 시작
2. 사용자 이동 중 분기점마다 노드를 그래프에 push (LIFO)
3. 복귀 명령 발생 → 그래프 pop하며 역경로 계산 → `state=3`(백트래킹)
4. 각 스텝마다 `turnAngle`/`distanceCm` 갱신해 ESP32로 전송
5. ESP32는 `turnAngle` 부호에 따라 좌/우 모터 중 하나만 구동
6. 진행 중 GPS 재획득 시 → `state=1`(아웃사이드) 복귀

## 8. 성능·제약 고려사항

| 항목 | 내용 |
|---|---|
| 센서 샘플링 | 폰 센서 화면 꺼짐 상태에서 끊길 수 있음 → Foreground Service + WakeLock, 실측 필요 (목표: 50Hz 이상, 30분 연속) |
| BLE 연결 | 1개로 단순화되어 이전 안(2개 동시 연결)보다 안정성·배터리 면에서 유리 |
| BLE 지연 | `seq` 필드로 유실률·지연 측정, 11월 필드테스트에서 확인 |
| 배선 | 허리→손목 배선 길이·유연성 확보 필요. 팔 굽힘 반복에 대한 내구성 테스트 필요 (단선 위험) |
| 전원 | ESP32·배터리가 1세트로 줄어 무게·소비전력 이전 안보다 유리 |
| 자기장 왜곡 | 실내 지자기 왜곡 시 헤딩 오차 → 자이로·지자기 상보 필터로 완화 |

## 9. 참고: HW 부품 목록 (예시, 미확정)

> **이 표는 변경 가능하다.** 위 1~8장 인터페이스 정의는 아래 부품이 바뀌어도 유지된다.

| 부품 | 예시 모델 | 수량(예시) | 역할 |
|---|---|---|---|
| ESP32 개발보드 | ESP32-DevKitC (WROOM-32) | 1 사용 + 1 예비 | 허리 유닛 메인 컨트롤러 |
| 진동모터 | 코인형 ERM 10mm 3V | 좌우 각1 + 예비2 | 손목 햅틱 출력 |
| 모터 드라이버 | MOSFET(2N7000 등) + 다이오드 | 좌우 채널 각1 + 예비2 | 모터 스위칭, 허리 유닛 내부에 위치 |
| 전방 거리센서 | VL53L0X (ToF) | 1 | 장애물 감지, 허리 유닛에 전방 장착 |
| 배터리 | LiPo 500~1000mAh | 1 사용 + 1 예비 | 허리 유닛 전원 (ESP32+모터 2채널 감당) |
| 충전 모듈 | TP4056 | 1 사용 + 1 예비 | 배터리 충전 |
| 수동전환 버튼 | 택트 스위치 | 1 | 모드 수동 전환, 허리 유닛에 부착 |
| 손목 연결 배선 | 2심 코일 케이블 또는 실리콘 피복선 | 좌우 각 1 (+예비) | 허리 유닛 → 손목 모터, 팔 굽힘 대응 |
| GPS / IMU | (구매 없음, 폰 내장) | — | 위치·방향 계산 |
